# NotebookLM 簡報生成 Prompt：因果關係圖版本

請根據我上傳的資料，幫我製作一份給國中生聽的專題簡報。

簡報主題：
「VIVE Eagle Assistive Scene Reader：用智慧眼鏡與 AI 幫助行人理解前方路況」

目標觀眾：
國中生，可能沒有程式設計、AI 或智慧眼鏡背景。請使用容易懂的生活例子，不要使用太艱深的工程術語。如果需要提到技術，請用比喻解釋。

簡報風格：
- 清楚、溫暖、像在介紹一個能幫助人的科技作品。
- 不要像商業廣告，也不要誇大成果。
- 請誠實說明目前成果與尚未完成的部分。
- 每張投影片文字不要太多，適合口頭報告。
- 每張投影片都附上簡短講稿。

建議簡報長度：
10 到 12 張投影片。

## 必須包含的內容

### 1. 專題名稱與一句話介紹

這是一個讓智慧眼鏡拍照，再由 AI 判斷前方路況，最後用大字與語音提醒使用者的輔助系統。

### 2. 為什麼需要這個專題

- 有些人走路時需要更多路況提醒，例如視力較弱、在陌生環境、夜晚或人行道障礙多的情況。
- 科技不是取代人，而是多一層提醒與協助。

### 3. 生活中的使用情境

- 使用者走在人行道上。
- 眼鏡取得前方照片。
- 手機 App 把照片交給 Gemini AI 判斷。
- AI 回傳「安全」、「注意」、「危險」等短提醒。
- 手機畫面與語音同步提示。

### 4. 系統怎麼運作

請用很簡單的流程說明：

智慧眼鏡拍照 -> 手機 App 接收照片 -> Gemini AI 判斷路況 -> App 顯示大字提醒 -> 語音朗讀提醒。

### 5. 插入一張「智慧眼鏡科技對生活的因果關係圖」

這張圖請做成系統思考的因果關係圖，不要做成普通流程圖。

圖上要有：

- 變數節點：
  - 路況辨識準確度
  - 提醒清楚度
  - 使用者信任
  - 使用頻率
  - 使用回饋
  - 系統改善
  - 生活獨立性
  - 外出意願
  - 誤判風險
  - 隱私疑慮
  - 過度依賴 AI

- 箭頭上要標 `+` 或 `-`：
  - `+` 代表正相關：A 增加時，B 也增加；A 減少時，B 也減少。
  - `-` 代表負相關：A 增加時，B 減少；A 減少時，B 增加。

- 有時間延遲的地方請標 `Delay`：
  - 使用回饋 -> 系統改善：需要時間整理與修改。
  - 系統改善 -> 路況辨識準確度：需要測試後才看得出改善。
  - 使用者信任 -> 外出意願：信任累積需要時間。

請至少畫出兩個回饋迴路：

#### R1 強化迴路：越用越好

路況辨識準確度 `+` -> 提醒清楚度 `+` -> 使用者信任 `+` -> 使用頻率 `+` -> 使用回饋 `+` -> 系統改善 `+` -> 路況辨識準確度

請標示：
- 這是強化迴路 R1。
- 意思是：系統越準，使用者越願意用；越多人使用與回饋，系統就越有機會改善。
- 其中「使用回饋 -> 系統改善」和「系統改善 -> 路況辨識準確度」有 Delay。

#### B1 平衡迴路：風險會降低使用

使用頻率 `+` -> 誤判風險暴露 `+` -> 使用者信任 `-` -> 使用頻率

請標示：
- 這是平衡迴路 B1。
- 意思是：使用越多，就越可能遇到 AI 判斷不準的情況；如果使用者覺得不可靠，信任會下降，使用頻率也會下降。

#### B2 平衡迴路：隱私疑慮會限制推廣

使用頻率 `+` -> 拍到路人或環境資料的機會 `+` -> 隱私疑慮 `+` -> 使用者信任 `-` -> 使用頻率

請標示：
- 這是平衡迴路 B2。
- 意思是：科技越常被使用，就越需要注意隱私；如果隱私沒處理好，大家會比較不放心。

#### R2 生活自信迴路

提醒清楚度 `+` -> 生活獨立性 `+` -> 外出意願 `+` -> 使用頻率 `+` -> 使用回饋 `+` -> 系統改善

請標示：
- 這是強化迴路 R2。
- 意思是：提醒越清楚，使用者越有安全感，也可能更願意外出。
- 其中「使用者信任 -> 外出意願」可以標 Delay，因為信心不是馬上建立的。

請在簡報中用國中生能懂的方式解釋：

- `+` 不代表好，只代表兩個變數同方向變動。
- `-` 不代表壞，只代表兩個變數反方向變動。
- `Delay` 代表影響不是馬上發生，需要一段時間。
- 強化迴路會讓變化越來越明顯。
- 平衡迴路會限制或拉回系統。

### 9. 還沒完成的部分

- AI 可能誤判，所以不能完全取代人的判斷。
- 拍照可能牽涉路人隱私，要避免保存不必要影像。
- 對使用者的提醒要簡短，不造成混亂。
